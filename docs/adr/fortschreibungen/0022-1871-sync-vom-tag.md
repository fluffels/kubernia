# Fortschreibung #1871 (2026-10-22): Sync von einem Tag, Drift-Gate rot bei ungetaggtem oder unsauberem Stand

Ergänzt [ADR 0022](../0022-dark-factory-kern-und-verteilung.md) (F10, Teil 1); die Fortschreibung steht als Datei (siehe [Fortschreibung zu ADR 0013](0013-1860-fortschreibungen-als-dateien.md)). Hebt die Grenze „der Sync läuft aus einem Arbeitsbaum“ aus der Fortschreibung #1613 auf.

- **Quelle ist ein Tag:** `factory-sync --quelle <repo> --tag <name>` liest jede Einheit aus dem Tag (`git ls-tree` einmal für den Baum und die Modi, `git cat-file --batch` mit `<commit>:<pfad>` für die Inhalte, inhaltsgleich zu `git show <tag>:<pfad>`; einzelne Pfade ohne Treffer im Cache über `git show`). Das Ausführbar-Bit ist der Modus `100755` aus dem Baum, auf jeder Plattform. Arbeitsbaum und Commits nach dem Tag ändern das Ergebnis nicht. Die Länge im Batch-Kopf zählt Bytes, erst danach wird UTF-8 dekodiert.
- **Nur Tags:** aufgelöst wird `refs/tags/<name>^{commit}`; ein Branch gleichen Namens zählt nicht (eigene Meldung „Branch, kein Tag“), ein fehlender oder ungültiger Name, eine Quelle ohne Git und ein ungetaggter Stand ohne `--tag` enden mit Exit 1 und schreiben nichts. Bei einem annotierten Tag steht der aufgelöste Commit im Stand, nicht das Tag-Objekt. `--tag` mit `--entwurf` und `--tag` ohne Namen sind Aufruffehler (Exit 2).
- **Sync-Stand Version 2:** `quelle: { commit, tag, sauber: true }` (Reihenfolge der Schlüssel fest). Ein Stand der Version 1 bleibt strukturell lesbar, ist aber rot (siehe unten); es gibt keine Datenmigration, ein Ziel synct neu.
- **Entwurfs-Sync:** `--entwurf` liest wie bisher den Arbeitsbaum (Ausführbar-Bit aus dem Dateisystem, `sauber` aus `git status`), der Stand trägt keinen `tag`; der Lauf meldet, dass das Drift-Gate im Ziel rot bleibt. Gedacht zur Probe, nie als Stand eines Projekts.
- **Drift-Gate:** rot, wenn der Sync-Stand keinen (oder einen leeren) `tag` hat oder `sauber` nicht `true` ist; die Meldung nennt den Weg „von einem Tag neu syncen“ mit dem Aufruf samt `--tag <name>`. Die Einheiten-Prüfung läuft weiter, alle Befunde erscheinen zugleich. Jede andere Version als 1 oder 2 gilt als kaputt. In diesem Repo ändert sich nichts: ohne Sync-Stand entfällt die Besitz-Prüfung, dieses Repo ist bis F10 die Quelle.
- **Rollen-Pfade als Einheiten (Teil-AK aus #1837):** der Sync bricht ab, wenn einer der Rollen-Pfade (`ROLLEN_PFADE`) ohne `PROJEKT_ROLLEN` im Quell-Manifest keine ganze, verteilte Einheit ist (also Planer, Umsetzer, Lens und Gruppe). Der Ticket-Skill gehört dem Projekt (Fortschreibung [#1850](0022-1850-ticket-skills-als-quellen.md)), steht nicht im Manifest und erzeugt nur einen Hinweis, wenn die Datei im Ziel fehlt: das Projekt legt sie dort selbst an.
- **Grenze 1:** Die Rollen-Prüfung läuft im laufenden Sync-Skript, im Ziel meist dem alten, nicht im Skript des Tags. Benennt ein neuer Kern-Stand einen Rollen-Pfad um, prüft das alte Skript gegen die alte Liste; der Weg ist ein Sync mit dem Skript des neuen Stands.
- **Grenze 2:** Ein per `git tag -f` verschobener Tag bleibt unbemerkt, Tag-Signaturen werden nicht geprüft; `sauber: true` bedeutet nur „aus einem Tag gelesen“, nicht „der Tag ist unverändert“.
- **Entscheidung (Leser):** `git cat-file --batch` statt je Datei ein `git show`, weil der echte Besitz hunderte Einheiten hat und jeder Git-Aufruf unter Windows rund 50 ms kostet; der Puffer ist auf 256 MiB gesetzt (der Standard von 1 MiB reißt beim echten Besitz).
